## Visual startup follow-up

The user confirmed the native window and configured monitor mode were visible.
Their build-1279 screenshot nevertheless showed “Setup required” and no activity
while the installed CLI/daemon were healthy. A diagnostic built from the same
Swift transport/model sources successfully fetched both authenticated review and
dashboard snapshots in the guest. The user clicked Refresh and confirmed that
activity appeared and the sidebar changed to “All services operational”; their
second screenshot documents the recovered dashboard.

Commit `98a96896` adds active-view recovery: refresh on activation and retry
unavailable daemon/dashboard reads when a CLI installation exists. Leaving the
active view cancels retries. Four regression tests cover delayed daemon startup,
dashboard-only failure, an absent installation, and cancellation. Build 1280
contains this fix. A controlled check launched build 1280 with the daemon stopped
and restored the launchd service after eight seconds. CLI health recovered;
the delayed-daemon recovery itself was not visually observed. After the later
cold boot and reopening, the user explicitly confirmed Overview loaded and
showed “All services operational” without clicking Refresh. Automatic startup
on reopening therefore passes; the earlier manual refresh is not counted as
that evidence.

The build-1280 app and DMG were submitted with the existing local App Store
Connect key: the host keychain profile was unavailable and a profile-save attempt
failed with “User interaction is not allowed.” No keychain permissions were
relaxed. The signed app was preserved after that initial submission failure,
then submitted, stapled, verified, and packaged without rebuilding or re-signing.

## Live-agent follow-up

A bounded Codex CLI 0.156.1 task attempted to write and verify one benign
workspace file. It did not complete successfully. Initial harness issues
included missing runtime helpers and nested sandbox incompatibility; these
are not product acceptance passes. The final invocation used explicit
`agentjail run --require-tunnel` with AgentJail OS isolation retained, and
failed before launching the task: `session_socket_timeout`, provider unavailable
after two start attempts, `/tmp/agentjail.sock` absent. macOS still listed the
1280 extension as activated and enabled. The user reported no permission dialog.
The root cause remains unconfirmed. A subsequent process sample captured the
provider's listener thread repeatedly in `accept`; source inspection found its
error branch retries unconditionally, including after listener shutdown. This
is a lifecycle concern to investigate, not proof of the socket-loss cause.

Only the documented temporary Codex auth cache was copied to the disposable
guest; no host settings, sessions, or plugins were copied. Cleanup removed the
cache after each attempt, including failures, and a separate check confirmed
it absent. A bounded scan of 105 local test/audit files found zero exact matches
for credential values from that cache and zero scan errors; this is not a
comprehensive credential-leak guarantee. Earlier capture warnings indicated
body-encryption keyring access was unavailable and require separate follow-up.

A host capture of the Tart window independently confirms the loaded Overview,
“All services operational,” and no permission dialog. It is retained locally as
`build/age293-evidence/age293-1280-overview-loaded.png`. Later captures failed
while the host reported its screen locked; those failures provide no visual
acceptance evidence. A second controlled delayed-daemon check restored the
daemon successfully, but its UI transition could not be captured.

## Fixes discovered by acceptance

- `c4392ced`: DMG packaging preserves the existing notarized bundle instead of
  implicitly rebuilding it. Installer pins both bundle identities and Apple
  signing team, matches versions, and requires notarized Gatekeeper acceptance.
- `e121fa8d`: profile preflight rejects the missing system-extension entitlement.
  Build 1277 passed notarization but macOS refused to launch it; runtime logs
  identified the stale profile. Regenerated profiles resolved the failure.
- `7e477e18`: explicit-enforce network asks block without approval. Build 1278
  forwarded them; local HTTP/1 and HTTP/2 tests reproduced that behavior before
  the fix. Build 1279 proves the corrected response and durable record.

Validation: affected Go packages pass with the race detector; post-commit Go
build, vet, and affected-package tests pass. Native suite: 141 XCTest tests and
35 Swift Testing tests pass. Installer rejection/rollback tests pass. The stale
profile was separately verified to fail before compilation. ShellCheck passes
with existing SC2016/SC2155 diagnostics excluded.
