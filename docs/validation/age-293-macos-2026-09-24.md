# AGE-293 macOS release candidate — 2026-09-24

## Decision

**Not cleared for public release.** Candidate 1.9.0 (1281) is locally signed,
notarized, and stapled. Clean Finder installation and the pre-reboot runtime
checks below passed. Terminal-upgrade launch behavior, post-reboot networking,
and the complete release gate remain open. No tag, push, public release, or
host installation was performed.

## Environment and installation

Fresh Tart VM `age293-release-1281`, macOS 15.7.7 (24G720), cloned from the pinned
vanilla image digest `57a83b1b52f928f5b11b0963927178fd6c4cac52c315279f227c27cc5ab81587`.
SIP was enabled. Gatekeeper was explicitly enabled before installation because
the vanilla image initially had assessments disabled.

The DMG was given synthetic Safari download quarantine. This was not a real
browser download. An initial command-line app copy launched translocated and
correctly requested moving to Applications. A subsequent actual Finder drag
from the mounted DMG to Applications passed normal Gatekeeper Open approval,
with quarantine preserved and a Notarized Developer ID assessment.

Fresh Finder launch automatically installed local CLI, daemon and hooks;
Overview loaded without Refresh. Before opting in, macOS listed zero system
extensions. Overview showed network monitoring not installed, the sidebar
showed healthy local services with network off, and Policies explained which
rules require network monitoring. Network activation was initiated explicitly
from the Network page; the user approved the macOS extension setting. Exact
version 1.9.0/1281 then reported activated/enabled.

A synthetic local Codex history fixture with a token-usage event appeared in
Local session history after cache refresh, separately labeled as not AgentJail
audit coverage. It did not increase audited counts. A metadata-only fixture
without usage was not surfaced by the existing collector; do not claim that
all local transcripts appear immediately.

The terminal installer dry run and replacement/upgrade both exited successfully
against this DMG. **After that replacement, relaunch and reboot launched the
app from App Translocation despite its destination being /Applications.**
The installed app retained quarantine `00c3`. This fails the converged native
launch acceptance; a successful installer exit is not sufficient.

## Runtime evidence before reboot

- Cold daemon restart followed by the first hook: allow with would-action deny
  for the disposable sensitive-file fixture; 222,164 microseconds; no unavailable
  fallback warning. Durable audit row matched the response.
- OS isolation: a workspace write succeeded; reading the disposable protected
  fixture through the sandbox failed. Monitor mode did not remove OS isolation.
- Network verdict matrix, using only benign example.com fixtures:

| Configured mode | Policy verdict | HTTP | Recorded action | Would-action |
| --- | --- | --- | --- | --- |
| monitor | deny | 200 | allow | deny |
| monitor | ask | 200 | allow | ask |
| enforce | deny | 403 | deny | empty |
| enforce | ask | 403 | ask | empty |

The policy was restored to monitor afterward. Five further consecutive required-
tunnel sessions each returned HTTP 200. This finite check does not prove the
absence of other lifecycle failures.

A real Codex 0.156.1 console session, launched through AgentJail with a required
tunnel and its OS sandbox, created and verified the exact benign acceptance
file. Exit status was zero; the file was independently compared byte-for-byte.
The hook audit contained the shell operation and the network UI showed 61
session-associated events. Hook and network session IDs differed; do not claim
an exact ID join. Captured body files had the encrypted AJBODY header, and no
plaintext-keychain warning was observed in this console test. Temporary guest
authentication was removed and independently confirmed absent.

**Compatibility caveat:** Codex retried WebSocket streaming five times with
“Attack attempt detected” before HTTPS fallback completed the task. The task
passed, but this was not a clean transport compatibility pass. Similar wording
exists in AGE-297; shared root cause has not been established.

## Reboot and cold boot

The daemon restarted, policy remained monitor, and the exact 1281 extension
remained activated/enabled. However, the first required-tunnel HTTPS request
timed out after 30 seconds; its audit error was upstream request: context
canceled. Direct guest HTTPS also timed out for example.com, apple.com, and
1.1.1.1. Host HTTPS to example.com succeeded.

A complete VM shutdown/start did not restore direct guest TCP connectivity.
Guest DNS resolved normally and the local gateway answered ping. During the
latest direct-request failure there was no AgentJail extension process running.
A fresh independent vanilla control VM (`age293-network-control`, no AgentJail
app and zero system extensions) also timed out connecting to example.com. This
establishes an environment failure independent of AgentJail installation, but
does not identify its cause. **Post-reboot network acceptance remains incomplete.**

The app still launched translocated after cold boot. Do not count this run as
an automatic healthy Overview acceptance for the terminal-upgrade path.
